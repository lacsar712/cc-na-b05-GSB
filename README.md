# 航标灯光巡检台

登记航标实测光强和方位偏差，服务端当场给出合格或不合格。页面由 Django 模板直接渲染，浏览器不另跑一套单页应用。

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3190 |
| 应用 | http://localhost:8190 |
| PostgreSQL | localhost:54390 |

## 账号

| 用户 | 密码 | 权限 |
|------|------|------|
| keeper | light123456 | 可登记、可调整坎德拉上限 |
| watch | watch123456 | 只读（含被拒灯光页与上限履历） |

## 坎德拉上限

- 当前上限保存在数据库里，初始 2000 坎德拉，keeper 在「坎德拉上限」页调整。
- 每次改动写入履历：旧值、新值、操作者、时刻。
- 登记时实测光强超过当前上限即被拒收，不进入总表，转而记入「被拒灯光」页：灯号、所填亮度、当时上限、拒绝时刻。
- 被拒行保存的是被拒那一刻的上限快照，之后调整上限不会改写旧行。
- 未越上限的填写照常按光强与方位判定入库。

## 启动

```bash
cd projects/11-nav-aid-inspection
docker compose up --build
```

## 验收

1. 打开 http://localhost:3190 ，用 keeper 登录，列表里 LH-01 合格、LH-09 不合格。
2. 再登记一条光强低于要求的记录，结论为光强不足。
3. 换 watch 登录，没有登记入口；直接提交登记会拒绝。
4. keeper 把上限调到 1000，登记一条 1400 的记录：被拒灯光页出现该灯号，当时上限记为 1000，总表不增加行。
5. 再把上限调到 1500，那条被拒记录仍显示当时上限 1000；履历页可看到 1000 与 1500 两次改动。
